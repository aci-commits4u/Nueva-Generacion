Proposal B keeps these boundaries. Add typed source namespaces: customer/merchant/tool/runtime. Provenance existence is checked deterministically; source entailment is assessed by interpretation, selective review and explicit human approval, with residual error measured. Critical unknowns never get an automatic PASS.

C adds allowlisted authenticated server identities, validated input/output schema, result size and age limits, destination allowlist, per-tenant scope, minimum necessary disclosed search arguments and enforced read-only execution. MCP annotations are hints, not permissions. Unknown remote tools remain disabled even if described as read-only. No arbitrary URL fetch, write tool, booking credential or payment instruction reaches the discovery agent.

On suspected prompt injection: quarantine or discard the affected observation, preserve customer requirements, report context unavailable, and hold decisions dependent on it. Do not rely on perfect injection detection: enforce permissions and deterministic gates even when malicious text is not recognized. A valid signature does not make policy text an instruction.

Risk reviewer exhaustion must be visible. If a review was required for a critical unresolved claim, it cannot be reported as completed when budget/provider fails. Keep the committed revision and pending uncertainty. Customer manual repair is recorded separately from an AI success.
