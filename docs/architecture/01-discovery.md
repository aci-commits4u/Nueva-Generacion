## What the code actually does

The model receives customer source messages, source catalogue, current draft, trusted clock, airport reference and merchant context separately (app/ai_pipeline.py:L732). Strict JSON generation is already used (L848). The server checks grounding, normalizes fields, preserves valid candidate claims, merges revisions and attaches a generated plan. Main clarification retains revision checks and clears approval after changes (app/main.py:L457). Persistence, provenance, selective review, merchant context and readonly tools already exist; the recommendation does not invent them.

The fragile seam is semantic reconciliation. The model emits a largely reconstructed field snapshot, followed by multiple preservation/reconciliation passes. app/main.py:L526 and app/ai_grounding.py:L2258 are concrete examples. Additional phrase rules can reject a correctly understood answer. Conversely source quotation alone cannot prove that a proposed meaning is correct.

Existing source auditing focuses on literal dates/money (app/source_coverage.py:L195); the selective answered-question diagnostic is specifically date-oriented (app/adaptive_intent.py:L814). Neither establishes arbitrary semantic completeness or question utility.
