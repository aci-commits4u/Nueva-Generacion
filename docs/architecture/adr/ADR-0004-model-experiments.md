# ADR-0004 — Separate model capability from architecture effects

Status: **Proposed experiment; model replacement OPEN** · 2026-10-16.

Evidence: app/ai_pipeline.py:L845 and app/foundry_client.py:L75 contain SDK seams. Current deployment uses structured model output, not ordinary unstructured chat. Low reasoning selection rests on a small latency lab, not a broad accuracy result.

Proposal: use one provider adapter with a versioned strict contract and normalized usage/error/timeout traces. Keep model fixed across A/B/C first, then compare reasoning levels and one qualified alternate deployment with the same architecture. Strict JSON ensures form, not truthful interpretation.

Do not provision a model based on a public catalogue row or assume gpt-oss-20b quota exists. Current Microsoft primary pages disagree on lifecycle wording, and public unit prices were unresolved. Resolve deployment-specific support, rate and student eligibility before a paid trial. No fallback can silently replace a failed live interpretation.

Consequences: fair attribution, less SDK drift, finite budget accounting; a faster model may still lose on constraint recall. Keep the incumbent if an alternate cannot satisfy the contract and paired quality/latency/cost criteria.
