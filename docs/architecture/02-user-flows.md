# User flows

| Flow | Success | Failure branch | Human step |
|---|---|---|---|
| Initial request | AI captures what was supplied and asks one material unanswered question or offers review | Ambiguous/unsupported meaning stays visible; provider failure preserves no fabricated result | Answer, correct, or inspect review |
| Follow-up and correction | Only intended records change; sets and explicit no-preference survive | Conflicting scope, stale revision or uncertain edit batch stays unapplied | Resolve concrete conflict or reload exact revision |
| Context lookup | Read-only tool gives provenance-labelled policy/offer data | Timeout/injection/unknown schema leaves observation unavailable; customer intent unchanged | Continue with clearly incomplete context or stop |
| Review and approval | Full canonical meaning and unresolved items visible; approve exact revision/digest | Missing mandatory facts, ongoing interpretation or changed digest prevents approval/checkout as appropriate | Explicit review and approval; never inferred from chat |
| Offer comparison | Verified facts satisfy supported approved rules | Missing facts/unknown constraints HOLD; eligible mismatch requires offer-specific exception | Inspect differences and explicitly accept only permitted exceptions |
| Simulated checkout/evidence | Idempotent receipt binds exact offer and approval | Invalid signature/binding/expired offer/unsupported condition cannot be waived | Confirm simulated action; download evidence |
| Interruption and capacity | Reload retains committed intent and approval state | Lost request, budget or stage limit produces precise reason; no silent parser/model fallback | Explicit retry, review, or leave; no repeated charge caused by UI replay |

Transfer: the same conversation and approval core handles flights, hotels and general shopping; the capability pack determines which requested meanings can be verified. Arbitrary intent can be discussed; unsupported predicates cannot receive a false verification badge.
