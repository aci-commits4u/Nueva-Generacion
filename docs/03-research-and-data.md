# Research and data (cite these; all public)

## The gap (from Mastercard's own spec — verified by reading and running the code)
- **Verifiable Intent (VI)**, launched **March 5, 2026** with Google; open source (Apache-2.0, draft v0.1) at github.com/agent-intent/verifiable-intent. Creates a tamper-evident SD-JWT chain: issuer → user → agent.
- Machine-checked: amount range, budget, allowed merchants/payees, allowed line-item IDs, recurrence (8 constraint types).
- `prompt_summary` (L2: "Human-readable description of the user's delegated intent"; L3b: agent's selection summary) is **OPTIONAL**.
- Spec: *"descriptive fields (product description, brand, color, size) are informational and not subject to automated verification."*
- Security model §2.5: *"VI does not define how disputes are initiated, routed between parties, escalated, or resolved. It does not assign liability, specify chargeback codes, or prescribe arbitration procedures."*
- VI **supports custom constraint types** (constraints.md §6.1) — we use this.
- Google **AP2** IntentMandate has `natural_language_description` ("generated by the shopping agent, and confirmed by the user"), `requires_refundability`, `user_cart_confirmation_required`.
- **Insight:** VI proves the agent was *allowed* to buy; nothing checks it bought what the person *meant*.

## Law & liability (published analysis; not legal advice)
- **Goodwin (June 2026):** Reg E — "a transfer is presumed authorized if a consumer furnishes credentials to authorize an agent." Reg Z — consumers may dispute goods "not accepted"/"not delivered as agreed"; **"the merchant bears the loss in practice."** Their example: an agent booking a connection that is **"technically compliant but unworkable."** Recommends precise delegation, retrievable records of what was approved, pause-and-confirm checkpoints, surfacing refund terms early.
- **Target** terms (Mar 2026): agent purchases are "transactions authorized by you."
- **Amex** (Apr 14, 2026): covers erroneous purchases by registered agents (closed network).
- **California AB 316** (effective Jan 1, 2026): bars the defense that an AI's autonomy caused the harm.
- No agent-specific chargeback reason code exists. Mastercard codes used: **4837** (no cardholder authorization), **4853** (cardholder dispute / not as described), 4841 (cancelled recurring).

## Landscape
- **Mastercard:** Agent Pay (registered agents, Agentic Tokens), Agent Pay Acceptance Framework (no-code merchant verification via Cloudflare Web Bot Auth), Verifiable Intent, Agent Pay Trust Framework (identity, intent, controls, execution, intelligence), agent-initiated probability score (US testing, Oct 2026), Developers Agent Toolkit (MCP server for docs: `https://developer.mcp.mastercard.com`).
- **Visa:** Trusted Agent Protocol, Intelligent Commerce, Agentic Ready program.
- **Google:** AP2, Universal Commerce Protocol. **OpenAI + Stripe:** Agentic Commerce Protocol, Buy it in ChatGPT.
- **Microsoft:** **Copilot Checkout** (Jan 2026; PayPal, Shopify, Stripe; merchant stays merchant of record; **Mastercard Agent Pay integration planned**). → natural pilot channel.
- **Amazon v. Perplexity:** injunction Mar 2026, reversed by Ninth Circuit Aug 2026.
